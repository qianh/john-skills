# 路由偏好（routing.md）

orchestrate 的"选型大脑"。**这是一份可编辑的偏好文档**，由 `config.sh init` 复制到用户配置目录后按自己的情况改；改动立即生效，改完可用 `config.sh check` 检查它引用的模型是否都已在 `models.conf` 配置。

- 引用的模型一律用 **`models.conf` 里的别名**（反引号包裹）；别名到真实模型参数的映射、能在哪些 Provider 上跑，都在 `models.conf`，这里不写。
- 下面是**起点默认值**，来自模型定位的常识判断，不是实测结论，用一阵后按真实表现回来改。
- 引用的模型没配置时的处理：选同角色里最接近的已配置模型，并在调度计划里说明；plan / review 一个可用模型都没有时，主控自己做并明说。

## 0. 调度确认

调度确认：自动

- `自动`（默认；本节缺失或写法不明时也按此处理）：亮出分工表后直接派发，用户中途改口再重排。
- `先确认`：plan 完成、最终分工表亮出后**停下**，让用户确认或改模型，再派发。
- 无论哪种模式，**T2 任务和不可逆动作（删除数据、部署、改生产配置等）一律停下确认**。

改这一行即可切换，下次调度生效。

## 1. 任务分级

| 级别 | 判据 | 调度方式 |
|---|---|---|
| **T0** | 单点改动、<2 文件、可逆、一眼能验证；或不改文件的问答、小范围排查 | **不拆分、不多模型**，但仍亮出一行声明，由 §3 选出的单个模型执行（见 SKILL.md Step 0） |
| **T1** | 常规：单模块、新增接口/页面、一般 bug、风险一般 | plan(1) → exec(1~N) → review(1) |
| **T2** | 跨多模块 / 碰钱·权限·迁移·生产 / 方案模糊 / 不可逆 | plan → 并行 exec → 双审 |
| **TR** | 纯审阅：对文档、需求、方案或代码做评审，**不改任何文件**，且范围较大（多文件 / 多份文档 / 需要独立视角） | 跳过 plan 和 exec，派 2 个不同家族的模型各审一遍，主控合并（见 §4） |

TR 与 T0 的区别：审阅范围很小（单个文件、一两处问题）按 T0 自己做；范围大或结论影响后续决策时用 TR。审阅之后若用户要求落实修改，改动部分另按 T0/T1/T2 分级。

判不准时取 T1（审阅类判不准取 TR），在调度计划里亮出分级，用户可一句话改。

## 2. 模型精简原则

一个任务流程里**最多用 2 个模型家族**（如 Claude + GPT、GPT + Grok），避免"品味"来回切换：
- 风格的唯一标准是**项目现有约定 + plan**，不是模型自己的偏好。上下文包里必须写明项目的风格约定和 plan 已定的取舍。
- reviewer 只审"是否符合 plan、需求和项目约定，有没有缺陷"，**不按个人口味提风格修改**；纯风格意见最多列为 P2。
- **一个任务流程只用一个 exec 模型**：不按代码 / 中文文本 / 联网等场景拆给不同模型；T2 并行的多个 executor 也用同一个模型。避免多个模型对同一任务理解不一致。

## 3. 按复杂度选型（主控一次判断）

先判断复杂度：
- **简单**：范围清楚、改动机械或局部、验收明确、低风险（含 T0 与简单 T1）。
- **复杂**：需要推理和取舍、跨模块、疑难 bug、风险 H、方案模糊（含 T2 与复杂 T1）。

| 阶段 | 简单 | 复杂 |
|---|---|---|
| plan | `gpt-6.1-sol` | `opus-5.5` |
| exec | `haiku-5.5` | `gpt-6.1-sol` |
| review | `gpt-6.1-sol` | `opus-5.5` |

规则：
- 主控本身就是该阶段选出的模型时，自己做，不另派。
- 简单档只接**边界清楚、验收命令明确**的活。
- 流程中途**不换 exec 模型**。简单档做不下去（2 轮修复仍不过、或发现需要判断力）时停下，向用户说明，由用户决定是否按复杂档重新起一个流程（带上账本，不从头来）。
- 想换某一档的 exec 模型，改上表那一格即可；其他已配置的模型（如 `sonnet-5.5`、`glm-5.3-flash`、`grok-4.7-build-fast`）保留在 models.conf，用户点名时可用。
- 风险 H 一律按复杂档。
- T0 也按本表选 exec 模型，不限于主控自己的模型。

## 4. review 规则

1. **reviewer ≠ executor**（同一模型不自审）。上表里简单档 haiku → gpt 审，复杂档 gpt → opus 审，天然满足，且都是跨家族。
2. T2 双审：`opus-5.5` + `sonnet-5.5`（均不同于 executor `gpt-6.1-sol`）。
3. reviewer **只读**，看 `git diff` 与验收结果，按 P1/P2 分级输出。

**TR 纯审阅**（没有 executor，审的是文档或现有代码）：
- 默认 `gpt-6.1-sol` + `opus-5.5` 各审一遍，两者不同家族。
- 主控自己读过的结论不算独立的一份，只在合并时用来核对。
- 主控按上下文包交付：要审的文件路径清单、用户的审阅问题、已知背景与关注点、输出要求（P1/P2，附文件路径+行号，只报真问题）。

只配置了一个模型时，"reviewer ≠ executor"无法满足：照常 review，但汇报里明确写出"同模型自审，独立性不足"。

## 5. 外壳（Provider）选择

外壳由 `models.conf` 决定，这里只写规则：

1. 主控 = 用户当前打开的那个 Provider，不强制换。
2. 目标模型的**默认外壳 = 它在 `models.conf` 里的第一行**；其余行是兜底。
3. 默认外壳 = 主控 → 优先用主控**原生 subagent**（Claude Code：Agent 工具带 `model`，只能选 Claude 系；其余 Provider 的原生 subagent 能力以其自身为准，拿不准就用 `dispatch.sh`）。
4. 默认外壳 ≠ 主控 → `dispatch.sh -p <外壳>`。
5. 默认外壳没装 / 登录失效 → 退到 `models.conf` 里下一行，并在汇报里说明。
