# 路由偏好（routing.md）

orchestrate 的"选型大脑"。**这是一份可编辑的偏好文档**，由 `config.sh init` 复制到用户配置目录后按自己的情况改；改动立即生效，改完可用 `config.sh check` 检查它引用的模型是否都已在 `models.conf` 配置。

- 引用的模型一律用 **`models.conf` 里的别名**（反引号包裹）；别名到真实模型参数的映射、能在哪些 Provider 上跑，都在 `models.conf`，这里不写。
- 下面是**起点默认值**，来自模型定位的常识判断，不是实测结论，用一阵后按真实表现回来改。
- 引用的模型没配置时的处理：选同角色里最接近的已配置模型，并在调度计划里说明；plan / review 一个可用模型都没有时，主控自己做并明说。

## 0. 调度确认

调度确认：先确认

- `先确认`（默认；本节缺失或写法不明时也按此处理）：plan 完成、最终分工表亮出后**停下**，让用户确认或改模型，再派发。
- `自动`：亮出分工表后直接派发，用户中途改口再重排。

改这一行即可切换，下次调度生效。

## 1. 任务分级

| 级别 | 判据 | 调度方式 |
|---|---|---|
| **T0** | 单点改动、<2 文件、可逆、一眼能验证 | **不调度**，主控自己做 |
| **T1** | 常规：单模块、新增接口/页面、一般 bug、风险一般 | plan(1) → exec(1~N) → review(1) |
| **T2** | 跨多模块 / 碰钱·权限·迁移·生产 / 方案模糊 / 不可逆 | plan → 并行 exec → 双审 |

判不准时取 T1，在调度计划里亮出分级，用户可一句话改。

## 2. plan 选型

| 条件 | 模型 |
|---|---|
| 默认（T1、T2） | `opus-5.5` |
| 主控本身就是该模型且任务为 T1 | 主控自己 plan，不另派 |

planner **只读**。产出必须是可直接派发的任务清单（格式见 SKILL.md Step 1）。

## 3. exec 选型

| 任务特征 | 模型 |
|---|---|
| 复杂逻辑、算法、重构、疑难 bug | `gpt-6.1-sol` |
| 通用功能实现、顺着既有代码风格改、前端、文档 | `sonnet-5.5` |
| 需要联网查资料、发散探索、spike 原型 | `grok-4.7` |
| 机械批量：重命名、样板、格式迁移、补测试数据、补注释 | `deepseek-v4.1-flash`（代码类）/ `glm-5.3-flash`（中文文本类） |

规则：
- **风险 H 时廉价 executor 升格**：不用 flash 档，改用 `sonnet-5.5` 或 `gpt-6.1-sol`。
- 不确定归哪类时用 `sonnet-5.5`。
- flash 档只接**边界清楚、验收命令明确**的活；需要判断力的不要给。

## 4. review 选型

硬规则：
1. **reviewer ≠ executor**（同一模型不自审）。
2. **尽量跨模型家族**，不同家族盲区不同。
3. reviewer **只读**，看 `git diff` 与验收结果，按 P1/P2 分级输出。

| executor | T1 reviewer | T2 reviewer（双审） |
|---|---|---|
| `gpt-6.1-sol` | `opus-5.5` | `opus-5.5` + `sonnet-5.5` |
| `sonnet-5.5` | `gpt-6.1-sol` | `opus-5.5` + `gpt-6.1-sol` |
| `grok-4.7` | `gpt-6.1-sol` | `opus-5.5` + `gpt-6.1-sol` |
| `deepseek-v4.1-flash` / `glm-5.3-flash` | `sonnet-5.5` | `opus-5.5` + `gpt-6.1-sol` |
| 多个 executor 混合 | 选一个不在 executor 集合里的 | 同左，取两个不同家族 |

只配置了一个模型时，"reviewer ≠ executor"无法满足：照常 review，但汇报里明确写出"同模型自审，独立性不足"。

## 5. 外壳（Provider）选择

外壳由 `models.conf` 决定，这里只写规则：

1. 主控 = 用户当前打开的那个 Provider，不强制换。
2. 目标模型的**默认外壳 = 它在 `models.conf` 里的第一行**；其余行是兜底。
3. 默认外壳 = 主控 → 优先用主控**原生 subagent**（Claude Code：Agent 工具带 `model`，只能选 Claude 系；其余 Provider 的原生 subagent 能力以其自身为准，拿不准就用 `dispatch.sh`）。
4. 默认外壳 ≠ 主控 → `dispatch.sh -p <外壳>`。
5. 默认外壳没装 / 登录失效 → 退到 `models.conf` 里下一行，并在汇报里说明。
